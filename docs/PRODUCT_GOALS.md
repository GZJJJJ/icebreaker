# 破冰小子：产品目标与首版交付边界

> 目标方向已确认：完整产品原型；允许会话内经同意的冷场轻提示；增加摄像头辅助场景感知。
> 本文定义要做成什么，不表示功能均已实现。仓库旧材料中的商业报价、OpenVela 路线和历史能力描述不作为当前交付承诺。

## 1. 最终要做出的东西

面向主题咖啡馆 2–6 人自愿参与桌的 AI 桌面社交主持设备。

它结合经授权的视觉线索、语音活动和用户选择，帮助同桌的人开始交流，在需要时提供话题、简短接话或轻量活动；人们聊起来后，它应退到一旁。目标不是做一个让每个人轮流与 AI 聊天的通用音箱。

首版交付是一台可展示、可受控试用的完整原型，不是直接销售的商业产品。设备采用屏幕、麦克风、扬声器、可遮挡/关闭的摄像头和明确的实体操作，配基本桌面外壳；不要求首版定制 PCB、电池供电或脱离云端运行。摄像头关闭时，基础主持流程仍可使用。

后台允许继续使用 Python Gateway 和在线 Provider。正常活动开始后，参与者不需要操作电脑终端；准备环境、服务部署及开发诊断仍可由开发者完成。

## 2. 一次完整的使用体验

1. **待机与告知**：显示设备用途、连接状态、麦克风及摄像头的采集/上传状态；未加入时不主动主持或拍摄。
2. **自愿加入**：明确说明数据处理方式，参与者可拒绝；摄像头、图像上传及冷场轻提示分别征得许可，不能默认替所有人同意。
3. **确认场景与主题**：用户可以直接选模式和主题，也可以启用摄像头获取场景建议，再确认或纠正；获得一个易于回答的开场问题或小活动，允许跳过和换题。
4. **开始交流**：设备简短播报开场，屏幕保留当前话题。参与者自愿发言，不强制点名或轮流回答。
5. **适度协助**：用户主动请求时接话或换题；启用辅助模式时，可在保守条件下给冷场轻提示。
6. **暂停或结束**：随时停播、停止音视频采集/上传，或结束整场活动；结束后清除本次会话内容，再次加入是一场新活动。

“一场活动”与“一次录音问答”不同：主题、当前活动和必要上下文应能跨多轮问答保留；取消某次回复不等于结束整场活动，结束活动才清理其内容。

## 3. 首版必须具备的能力

- **主持流程**：加入、选主题、开场、接话、跳过、换题、暂停、结束，而不是只有单轮问答。
- **受控场景感知**：经许可采集画面，提供可见人数、桌面物品及可见活动线索；输出待确认的场景建议，不自动给参与者贴性别、关系或情绪标签。
- **主题内容**：少量完整主题包即可；旅行、电影、阅读是建议首批主题，具体内容再细化。不以 RAG 或主题数量作为验收目的。
- **中文界面**：能看懂当前话题、正在做什么、是否正在采集语音，以及下一步怎样操作；等待云端时有明确反馈。
- **可靠控制**：停止当前播报不依赖云端；打断后还能重新输入；“停播”“停麦/停上传”“结束活动”含义明确、不能互相冒充。
- **异常处理**：断网、云端失败、空识别等有可理解提示和恢复路径，不静默卡死或续播过期回复。
- **可演示形态**：设备、供电和基本桌面外壳可组合使用；参与者通过设备完成活动操作，不需要开发者逐轮敲命令。

具体使用哪个键、是否接入触摸、屏幕布局和外壳尺寸是后续设计事项，本文件不提前锁死。

## 4. 摄像头辅助场景感知

目标是“观察可见线索 → 推荐候选模式 → 用户确认 → 调整主持策略”，不是仅凭人数、外貌或姿态断定关系与内心状态。

| 可见线索或用户输入 | 可提供的建议 | 不应自动作出的结论 |
| --- | --- | --- |
| 画面中可见两人、饮品、面对面活动 | 双人聊天模式、轻松认识类话题 | 一男一女、情侣、暧昧、恋爱意图 |
| 可见多人及笔记本、文档等物品 | 多人交流或小会议候选，由用户确认 | 多人必然正在组会，或知道谁是同事/负责人 |
| 长时间缺少语音活动，加上可见人数/活动变化 | 在许可范围内建议“需要新话题吗” | 参与者尴尬、无聊、彼此喜欢或不喜欢 |

“恋爱/约会主题”可以由参与者明确选择，不依赖视觉推断性别、性取向或关系；选择后仍不强迫个人披露或亲密互动。“小会议模式”首版仅改变开场与议题提示方式，不自动扩展为会议纪要、员工评估或考勤系统。

首版先支持用户主动触发的场景快照；低频会话内辅助采样列入后续验证项，只能在单独授权后启用。人数是画面可见人数，不等于整桌真实人数；遮挡、光照、画面外人员都需要允许未知和手动纠正。不以持续视频上传作为默认实现。

ESP32-S3 负责图像采集、权限和停止控制，复杂图像理解交给 Gateway/视觉 Provider。现有文字 LLM 适配没有图像输入，视觉模型、费用、带宽及摄像头引脚/资源冲突均需另行验证，不能假设现有免费语音服务直接支持视觉。

## 5. 冷场轻提示的边界

这是经同意的辅助主持，不是情绪识别或“判断谁不合群”。

- 只在明确加入、同意启用的当前活动内工作，暂停、结束或断线时停止主动介入。
- 不因一次短暂停顿立即说话；触发条件应综合本地语音活动、持续停顿、最近提示及用户操作，采用保守阈值。获准的视觉线索只能作为补充，摄像头关闭或线索不足时不强行判断。
- 有人说话时不插话；不确定时优先不播报。误触发可打断、忽略或关闭，不能连续催促。
- 屏幕建议与语音轻提示应可区分；先屏幕提示、再确认播报是优先考虑的低打扰设计，最终交互与阈值需实测确定。
- 本地语音活动检测不等于持续录音上传。用于冷场判断的环境音处理与用户主动提交给 ASR 的语音必须有明确边界。
- 不承诺识别人脸、说话人身份、情绪、关系或多人重叠语音内容。

## 6. 隐私与数据目标

- 默认不自动拍摄、不持续上传环境录音；摄像头需要可见的开关/遮挡与采集提示。拍摄范围应限制在获准参与区域，未同意者在画面内时不得直接上传，优先调整取景或关闭摄像头。
- 明确显示麦克风采集与上传状态；参与者可以停止采集/上传。软件停采集不宣称为硬件电气隔离。
- 默认不长期保存原始录音、画面和完整转写；只保留当前活动必要的临时上下文，结束后清除，不建立人脸档案。
- 使用在线 ASR/LLM/TTS 或视觉服务必须告知哪些语音、文本或图像会发送给第三方；设备清缓存不等于第三方立即删除，不能作无法验证的承诺。
- 正式演示模式的日志应以状态、错误代码、耗时为主；开发阶段存在的 ASR/LLM 文本日志不能当成已经满足上述目标。

## 7. 做到什么算首版完成

### 功能验收

- 一桌参与者能通过设备完成：加入并选择感知/提示权限 → 确认场景和主题 → 开场 → 多轮接话 → 跳过/换题 → 暂停/恢复 → 结束并开启新活动。
- 摄像头开启且获准时能提供可纠正的场景建议；关闭摄像头不影响手动选择和基础主持，未授权、暂停和结束时不拍摄/上传。视觉误判不能直接触发未经确认的恋爱或会议模式。
- 打断发生在等待或播报阶段时，旧回复不再续播，下一轮仍可提交和收到回复；不能只用电脑上的替身测试判定真实链路通过。
- 冷场提示仅在许可状态和触发条件满足时出现；正常聊天、暂停、结束时不主动插话，误提示可停止。
- 断网和 Provider 失败能被看见，恢复后可再次使用；不会在无人确认时恢复旧录音或旧播报。
- 活动结束后，主题外的上次对话内容不会带入新活动；音视频采集和上传均停止。

### 体验验收

- 通过受控多人试用观察：是否有人因为提示开始交流、话题是否适合、设备是否抢话或催促、用户是否清楚怎样停用。
- “促进人和人交流”是核心指标；AI 回复次数、接口接通数和外设数量不是成功标准。
- 记录首音等待分布、本地打断延迟和故障情况。历史材料中的首音 P95 ≤3 秒、停播 ≤300 ms 是待验证目标，不是已达成事实；测试通过也不能替代声学和多人现场验收。

尚未规定试用规模、达标比例和最终性能门槛，需结合可用模型、场地与测试方法另行确认，不能事后为演示结果降低口径。

## 8. 当前进度与仍有的差距

已搭好语音和外设基线：ESP-IDF、Wi-Fi、Gateway、按键录音、ASR/LLM/TTS、扬声器、基本打断/重连及英文状态屏；活动流程第一版已支持加入、主题选择、暂停、恢复、结束清理和有限多轮上下文。

仍需完成产品层：中文交互、音视频权限、摄像头采集与视觉建议、保守冷场策略、基本外壳及真实多人试用。摄像头尚未接通，不能把目标文档当成当前能力。

已测长等待主要涉及云端识别波动、推理模型及整段串联处理；偶发“打断后无回复”的失败现场尚未捕获，不能断言所有软硬件问题均已排除。继续保留诊断，不因此无限阻塞产品功能开发。

## 9. 首版不做

- 从画面推断性别、性取向、恋爱关系、暧昧意图或内心情绪；人脸身份识别与个人档案。
- 未经许可的环境拍摄/上传、全天视频监控和自动会议记录。
- OpenVela 迁移、大模型端侧推理或全离线自由对话。
- 定制量产 PCB、量产认证、收费订阅、完整门店管理后台。
- 在当前免费云服务和指定推理模型上承诺商业级固定低延迟或无人值守可靠性。

这些可以是后续路线，但不能混入首版“完成”的定义。

## 10. 后续开发顺序

先完成整场活动状态与结束清理，再做场景模式、主题和跨轮主持上下文，然后补中文界面与明确的音视频权限控制；接通摄像头主动快照和可确认的视觉建议后，再验证声音与可见线索结合的保守冷场提示，最后通过桌面形态和多人受控试用验收。
